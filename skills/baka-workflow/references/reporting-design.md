# 报告与设计协作

## 周报

仅周报任务适用：只统计 `git log --author="$(git config user.name)"` 命中的本人提交，结合本周 work records 补充实际推进但提交未充分体现的工作，不把计划写成成果。必要时询问仓库外工作。

按项目分组，顶层 `●`、子项 `○`，中文一句一项，不加统计表、亮点总结或下周计划。输出 Markdown 原文，并在任务约定的报告目录保存 `weekly-reports/yyyyMMdd_hhmmss_weekly_summary.md`；仓库内落盘须在已授权的工作目录中，不为输出周报擅改其他 checkout。

## 页面设计

- 新网站或新页面默认由 Hallmark 定方向并做初版；已有页面整页重设计只在用户明确要求时用 Hallmark redesign。用户指定其他技能或分工时遵从。
- 初版后按任务需要使用 Impeccable critique／audit 评审，或 typeset／layout／clarify／adapt／polish 局部改进；不因工具可用扩大修改范围，评审的写入边界沿用通用规则。
- 两者共用已有 `DESIGN.md`（兼容 `design.md`），复用确认的字体、配色、tokens、组件和布局；没有时在授权开发范围记录确认的设计，不建立冲突的大小写版本。
- 交接保留主题、视觉记忆点和交互接线；通用审美偏好不覆盖已确认的品牌和项目规范。
- 用户、目标和约束记录在 `PRODUCT.md`，复用已有信息，仅按项目实际需要初始化，不批量写配置或开启 hooks。
- 所需技能在目标设备不可用时说明缺口，不擅自安装或替换用户已选工具；可在当前授权范围使用已有能力完成不依赖它的工作。
